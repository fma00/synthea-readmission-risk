`house_style(theme)` is `matplotlib.rc_context(HOUSE_RC | theme-colour keys)`; the theme sets `text.color, axes.edgecolor, axes.labelcolor, xtick.color, ytick.color` to `theme.ink`. It ALSO installs a scoped `logging.Filter` on the `matplotlib.font_manager` logger that drops the record `findfont: Failed to find font weight light ...` (matplotlib emits this on machines without a light face: verified on the dev machine; `findfont` caches its lookup, so the record is logged only for the FIRST lookup in a process unless the cache is cleared), added on entry and removed in a `finally` on exit, so no other record is affected and the filter does not outlive the context. Deviation from the owner's snippet (flagged, behaviour-equivalent): the snippet mutates global state (`pylab.rcParams.update`, `plt.figure`); this repo's rule (evaluate.py:225) is the Figure API with no pyplot global state, so the same settings go through `rc_context` and `matplotlib.figure.Figure`, and `MaxNLocator(5)` is the object `plt.MaxNLocator(5)` names.
`new_axes` must be called inside `house_style`; it does exactly: `Figure(figsize=(w*CM, h*CM), dpi=1200, layout="constrained")` with `FigureCanvasAgg(fig)` attached (VERIFIED: on a bare `Figure` the canvas is `FigureCanvasBase`, so `fig.canvas.draw()` is a no-op and constrained layout never runs; with `FigureCanvasAgg` attached `fig.canvas.draw()` runs the layout and `fig.canvas.get_renderer()` exists) (constrained layout is the one layout mechanism, so axis labels, tick labels and the title are kept inside the figure; no `tight_layout`, no manual margins), `fig.add_subplot(111)`, right/top spines invisible, `MaxNLocator(5)` on both axes, `fig.patch.set_alpha(0.0)`, `ax.patch.set_alpha(0.0)`.
`save_figure`: calls `fig.savefig(path, metadata=metadata, dpi=dpi, facecolor=facecolor)`; the format comes from the suffix (`.svg`, `.png`), so callers pass final-looking names. For SVG the caller passes `{"Title": ..., "Description": ..., "Date": None}` (no timestamp). For the PNG preview the caller passes `dpi=200` (explicit override of the figure's 1200 dpi; owner: "keep the PNG low res") and `facecolor=theme.preview_background`. VERIFIED on matplotlib 3.11.2: `savefig(facecolor=...)` and `transparent=False` do NOT override a figure patch whose alpha is 0 (the corner pixel stays `(255,255,255,0)`), so when `facecolor` is given `save_figure` temporarily calls `fig.patch.set_facecolor(facecolor)` and `fig.patch.set_alpha(1.0)` (the axes patch may stay alpha 0), saves, and restores the previous facecolor and alpha in a `finally`; with `facecolor=None` the figure is saved as is (transparent for SVG). Verified result: corner pixel `(13, 17, 23, 255)` for the dark background.
Themes: light `ink #1f2328`, `grey #6e7781`, `preview_background #ffffff`, series logistic regression `#0072B2`, calibrated XGBoost `#D55E00`; dark `ink #e6edf3`, `grey #8b949e`, `preview_background #0d1117`, series `#56B4E9` and `#E69F00`. Markers: circle (`o`) for logistic regression, square (`s`) for calibrated XGBoost (shape redundantly encodes the model).

**reliability.py**
```python
@dataclass(frozen=True)
class BinPoint: mean_predicted: float; observed_fraction: float; n: int; n_positive: int; ci_low: float; ci_high: float
def wilson_interval(k: int, n: int, z: float = 1.959964) -> tuple[float, float]   # (low, high); n >= 1 and 0 <= k <= n else ValueError
# Textbook Wilson centre/half-width, THEN: low = 0.0 if k == 0 else max(0.0, low); high = 1.0 if k == n else min(1.0, high);
# then low = min(low, k / n) and high = max(high, k / n). (Verified by a reviewer: the unclamped formula violates
# 0 <= low <= k/n <= high <= 1 in floating point for 282 (k, n) pairs with n < 400, e.g. low = -1.7e-18 at k = 0, n = 154, and
# high = 0.9999999999999999 at k = n, which would hand Axes.errorbar a negative yerr and make it raise.)
def bin_points(curve: list[dict[str, float]]) -> list[BinPoint]
def build_reliability_figure(curves: Mapping[str, list[dict[str, float]]], theme: Theme, *, size="half", height_cm=7.0) -> Figure
```
`curves` keys are model names; values are the `calibration_curve` list as `evaluate_probabilities` produces it: records with keys `mean_predicted`, `observed_fraction`, `n` (evaluate.py:55-65). On disk the run artifact `calibration_curve.json` is `{"calibration_curve": [records]}` (training.py:289); unwrapping that key is `load_curves`'s job, not `bin_points`'s.
`bin_points`: validates a non-empty list, all three keys present and finite, `n` an integer >= 1, `0 <= mean_predicted <= 1`, `0 <= observed_fraction <= 1`; reconstructs `k = round(observed_fraction * n)` and raises `ValueError` if `abs(observed_fraction * n - k) > 1e-6` (a bin of a 0/1 label has fraction exactly k/n up to float error ~1e-14; 1e-6 is a format check, not a statistical one); sorts the bins ascending by `mean_predicted` (stable) so the connecting line is monotone in x; attaches `wilson_interval(k, n)`. The sum check in `load_curves` is the ONLY authoritative reconciliation between a curve and its run (stated once, here); this per-bin check only validates the record format.
`build_reliability_figure` (call it inside `house_style(theme)`): title "Reliability, test window (development set)" (9 pt; MEASURED 6.71 cm wide in the 9 cm panel; the longer wording "Reliability on the held-out test window (development set)" measures 9.15 cm and is clipped, so it is not used; "development set" stays because CLAUDE.md slice-3 caveat 1 says the 2023+ window is not a virgin holdout); x label "Mean predicted probability", y label "Observed fraction positive" (the existing diagram's labels); the diagonal `ax.plot([0, L], [0, L])`, dashed, `theme.grey`, linewidth 1, label "perfectly calibrated"; per model in `MODEL_NAMES` order: `ax.errorbar(x, y, yerr=[np.maximum(y - ci_low, 0.0), np.maximum(ci_high - y, 0.0)], marker=theme.markers[m], markersize=3, linewidth=1, elinewidth=1, capsize=1.5, capthick=1, color=theme.series[m], label=MODEL_DISPLAY_NAMES[m])` (the connecting line and the interval bars share linewidth 1); legend `loc="upper left"`, `frameon=False` (the manual approval check includes whether the legend text overlaps the top bin's interval bar or the dashed diagonal; if it does, switch to `loc="lower right"`); the diagonal is drawn first but the legend handles/labels are passed explicitly (`ax.legend(handles=[*model_handles, diagonal_handle])`) so the order is models then diagonal. Axis limits: both axes from 0 to the same `L = 1.05 * max(max ci_high, max mean_predicted)` over all models, so the diagonal is y = x. KNOWN, ACCEPTED LIMITATION (measured on the real curves): for logistic regression 8 of 10 bins have mean prediction <= 0.0133, then 0.0243 and 0.0942; for calibrated XGBoost 9 of 10 bins are <= 0.0147 and 8 of those lie within 0.0103-0.0123, so its markers and bars nearly coincide; each bin has about 154 rows and about 4 positives. L (about 0.12) is set by the top logistic bin's Wilson upper bound. On linear axes both series therefore crowd the lower-left corner and XGBoost overplots itself. No x-offset or jitter is applied (it would misreport the x position). This is a likely approval issue; the owner judges it from the preview, and a log-scaled inset or zoomed second panel is only added if they ask. Wilson intervals treat rows as independent while Synthea patients contribute several stays, so they are narrower than the truth; the headline intervals in docs/results.md are patient-clustered bootstraps. The mean-predicted x position of a quantile bin is itself a sample statistic with no uncertainty drawn. The phase-2 caption must therefore say: "{n} quantile bins (10 for the reference run), 41 positives in total; vertical bars are 95% Wilson intervals with rows treated as independent, so they understate the uncertainty."

**topn_table.py**
```python
def format_topn_markdown(predictions: pd.DataFrame, n: int = 5) -> str
```
Input: the predictions frame as read from the parquet. Columns used (exact names, from `PREDICTION_COLUMNS`/`PREDICTION_SCHEMA` in scoring/store.py): `rank` (int), `risk_score` (float), `discharge_time` (tz-aware UTC timestamp), `admission_reason_description` (nullable string), `patient_id` (string). `is_top_n`/`top_n` are ignored (the 5 rows are the first 5 by rank even if `top_n` is smaller; with the real file `top_n` is 10). Raises `ValueError` listing any missing column among the five above, and unless the frame has at least `n` rows, the `n` smallest ranks are exactly 1..n, and `risk_score` is non-increasing over them. Output: a GitHub Markdown table, header `| Rank | Risk score | Discharged | Admission reason | Patient |` with the alignment row `|---:|---:|---|---|---|`, then n rows: rank as an integer, `risk_score` to 4 decimals, `discharge_time` as `YYYY-MM-DD` (UTC), `admission_reason_description` truncated to 48 characters (as `scoring/report.py`), a null shown as `(none)`, `|` escaped as `\|` and newlines replaced by a space, patient id shortened to its first 8 characters (synthetic ids; the full ids stay in the parquet). Ends with a single newline.

**assets.py**
```python
@dataclass(frozen=True)
class RunFacts: model_name: str; run_id: str; test_n_rows: int; test_n_positive: int
@dataclass(frozen=True)
class AssetConfig: tracking_dir: Path; experiment_name: str; predictions_path: Path; out_dir: Path; top_n_rows: int = 5
def load_curves(tracking_dir: Path, experiment_name: str) -> tuple[dict[str, list[dict[str, float]]], dict[str, RunFacts]]
def build_assets(config: AssetConfig, *, curve_loader=load_curves, predictions_loader=pd.read_parquet) -> list[Path]
```
`load_curves`: for each name in `MODEL_NAMES`, `resolve_run_id(tracking_dir, experiment_name, name)`; downloads `calibration_curve.json` with `MlflowClient().download_artifacts(run_id, "calibration_curve.json", tmp)` and unwraps the `calibration_curve` key; reads run metrics `test_n_rows` and `test_n_positive` (exact MLflow keys; logged at training.py:287 as `test_{key}` for the keys `n_rows`/`n_positive` produced at evaluate.py:112-113; stored as floats, converted with an integrality check). It raises `ValueError` unless for every model `sum(record n) == test_n_rows` and `sum(k) == test_n_positive` where `k = round(observed_fraction*n)` (the curve provably is the run's whole test window) AND the two runs' `split_assignment.csv` artifacts (training.py:~297; columns `encounter_id`, `partition`) have IDENTICAL sets of `encounter_id`s with `partition == "test"` (parsed with `pd.read_csv(path, dtype=str, keep_default_na=False)` and a check that the columns are exactly `['encounter_id', 'partition']`, the same convention as `scoring/runs.py::_read_assignment` (runs.py:111); a plain `read_csv` would turn an id spelled "NA" into NaN) (equal sums alone would not prove the same rows). The artifact downloads use `tempfile.TemporaryDirectory()` owned by `load_curves` and removed on exit; JSON/CSV are parsed inside the `with` block. Global-state hygiene: `resolve_run_id` sets the MLflow tracking URI as a side effect, so `load_curves` records `mlflow.get_tracking_uri()` first and restores it in a `finally`.
`build_assets(config, ...)`:
1. `curves, facts = curve_loader(tracking_dir, experiment_name)`; `predictions = predictions_loader(predictions_path)`.
2. Predictions provenance checks (`ValueError` on failure): the columns `model_name`, `model_run_id`, `as_of_date` contain no nulls and exactly one distinct value across the file (`nunique() == 1` and `notna().all()`; the single value is then `.iloc[0]`; `as_of_date` arrives from parquet as a `datetime.date` object column, so `f"{value:%Y-%m-%d}"` works, and a `pd.Timestamp` is accepted too); `model_run_id` equals `facts[model_name].run_id` for that `model_name` (a stale parquet from a different run would contradict the figure); `model_name` is in `MODEL_NAMES`; every row has `partition == "test"` (the caption claims held-out rows); `scoring_window_days` has exactly one distinct value.
3. Figures: for each theme in (`light`, `dark`): ONE `with house_style(theme):` block contains the whole sequence build -> draw -> save (`fig = build_reliability_figure(curves, theme)`, any `fig.canvas.draw()`, and both `save_figure` calls), because rc values such as `svg.fonttype` and `svg.hashsalt` and the lazily created tick properties are read at draw/save time, not at build time (VERIFIED: a figure built in the context but saved outside it wrote 0 `<text` elements and 48 glyph `<use>` paths instead of text); the same applies to every test that builds, draws or saves a figure; the SVG gets `metadata = {"Title": <figure title>, "Description": f"Reliability diagram. Source: MLflow experiment {experiment_name}, runs {run_ids}; {rows} test rows, {positives} positives; {bins_text}; 95% Wilson intervals with rows treated as independent (indicative only); development-set quality, not a virgin holdout.", "Date": None}`, where `bins_text` is `f"{n} quantile bins"` when both curves have the same length n and `"{a} and {b} quantile bins (logistic_regression, xgboost_calibrated)"` otherwise (`evaluate._quantile_bin_ids` can return fewer than 10 bins; nothing is hard-coded) where `run_ids` is `", ".join(f"{name}={run_id}" for name in MODEL_NAMES)` with FULL run ids and `rows`/`positives` are the reconciled integers from `RunFacts`; the PNG preview is saved with `dpi=200`, `facecolor=theme.preview_background` (opaque so each theme is reviewable on any viewer; the committed SVGs stay transparent).
4. Table: `format_topn_markdown(predictions, config.top_n_rows)`; `sample_topn.md` = a first caption line that is EXACTLY this f-string (single line, no other variant): `f"Sample Top-{n}: ranks 1-{n} of {len(predictions)} discharges scored in the {scoring_window_days}-day window ending {as_of_date:%Y-%m-%d}, {MODEL_DISPLAY_NAMES[model_name]}. Demo over held-out rows (development set), not new-data scoring."` (`scoring_window_days` is the file's single distinct int; `as_of_date` the single `datetime.date`) + a second line `Risk scores are rankings, not absolute risks: the test-window prevalence is {p:.2%} ({k} of {n:,}) and the models under-predict on average.` (the trailing clause is included only when the data support it: the mean predicted probability of a model is `sum(bin n * bin mean_predicted) / sum(bin n)` from its curve, which is exact because the quantile bins partition the test rows; if either model's mean is >= `p`, the clause is omitted, so a regeneration on another population cannot print a false claim) + blank line + the table. (`len(predictions)` is the parquet row count, i.e. all discharges scored in ONE window; the wording names the window so a reader does not confuse that count with the 1,539-row test window of the figure; the real file yields `Sample Top-5: ranks 1-5 of 42 discharges scored in the 30-day window ending 2025-06-30, Logistic regression. Demo over held-out rows (development set), not new-data scoring.`) Phase 1 previews are shown to the owner together with the proposed phase-2 captions (reliability and table), so the approval is made with the caveats in view.
5. Writes: after steps 1-4 have validated and rendered in memory, `out_dir` and `out_dir/preview/` are created with `mkdir(parents=True, exist_ok=True)` (the default `docs/img/` does not exist yet), and ONLY THEN is the temporary directory `out_dir/.tmp-<pid>/` created. Everything is written into that temporary directory under its FINAL file names (so matplotlib infers the format from the suffix), then each file is moved with `os.replace` by suffix: `*.png` into `out_dir/preview/`, every other file into `out_dir`, and the temp directory is removed in a `finally`. Atomicity is per file; a crash during the move loop can leave a mix of old and new files, which is acceptable for regenerable review assets and is stated here instead of claimed away. A failure before the move loop writes no FILE into `out_dir` and leaves existing files unchanged (an empty `out_dir`/`preview` directory created by the failed run may remain; that is not treated as touching it). Returns the list of final paths (4 figure files + `sample_topn.md`).

### UX flow
`mlflow/` store + predictions parquet -> `load_curves` (resolve runs, download curves, reconcile with run metrics) -> provenance checks on the parquet -> `bin_points` (Wilson intervals) -> `build_reliability_figure` x {light, dark} -> `save_figure` (SVG + opaque low-res PNG preview) ; predictions parquet -> `format_topn_markdown` -> `sample_topn.md`. Review step: the implementer opens each preview PNG and shows it to the owner in chat with the file paths; the owner approves or requests changes; only then does phase 2 run.

### Data handling
Touches only held-out (test-partition) outputs of already-finished runs; nothing is fitted or re-split, so there is no new leakage surface. The reliability points ARE development-set quality (CLAUDE.md slice-3 caveat 1), stated in the figure title and the table caption. Both models' curves come from the same experiment and test partition (reconciled by the sum checks). The predictions file's `model_run_id` must equal the plotted run of that model. No randomness anywhere (Wilson is analytic; no bootstrap or sampling). Determinism, stated precisely: within one environment (same matplotlib and font setup) the SVG bytes are identical for identical inputs (fixed `svg.hashsalt`, `Date: None`, fixed font stack); across machines or matplotlib versions they may differ, and only same-process determinism is tested. The layout is measured with the local fallback face (DejaVu Sans) while the viewer draws the SVG with its own sans-serif, so the approved preview is only approximately what GitHub renders and the `Description` embeds the store-derived run ids and counts, so they are deterministic per input, not constant; PNG bytes are best-effort only and the PNG previews are never committed. Synthetic data only; patient ids are shortened. The mlflow store and the predictions parquet are gitignored, so the committed SVGs and table are the only published derivatives (a reader cannot regenerate without running the pipeline; the README already says the store is not published). Global state: `rc_context` and a scoped logging filter (removed in `finally`) in `house_style`; the MLflow tracking URI is restored by `load_curves`.

### Failure modes
- `mlflow/` store missing: `resolve_run_id`'s `_require_store` raises `FileNotFoundError`; experiment missing or deleted, a model with no or more than one FINISHED run: `ValueError`. Both map to exit 1 with `ERROR:`.
- `calibration_curve.json` missing or malformed (no `calibration_curve` key), empty curve, non-finite values, `n < 1`, `observed*n` non-integral, curve totals not matching `test_n_rows`/`test_n_positive`, the two models disagreeing on test rows -> `ValueError`, nothing written.
- A bin with 0 or `n` positives: Wilson yields a finite interval inside [0, 1] (lower exactly 0 / upper exactly 1 at the extremes); a single-bin curve still plots.
- Predictions parquet missing -> `FileNotFoundError`; fewer than `n` rows, ranks not 1..n, scores increasing, more than one distinct `model_name`/`model_run_id`/`as_of_date`, or `model_run_id` different from the resolved run -> `ValueError`; null description -> `(none)`; `|` in a description escaped.
- Matplotlib `findfont` light-weight warning: handled by the scoped filter in `house_style`, covered by a test.
- A failure while rendering or while writing the temp directory leaves existing files in `out_dir` unchanged and writes no new file there (validation and rendering happen before any directory is created); the temp directory is always removed.
